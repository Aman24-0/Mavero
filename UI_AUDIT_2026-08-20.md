# MAVERO full browse UI audit — 2026-08-20

## User screenshot findings

The mobile detail view has a very large empty vertical region between the top navigation/metadata/actions and the recommendation rail. The page appears to lose or fail to render its hero media, leaving a blank black field while a favorite heart floats by itself. This makes the page feel broken rather than cinematic.

The same route exposes several actions with overlapping meaning: Watch now, My list, Share, and a separate heart/favorite action. The controls are visually scattered across multiple rows, creating clutter. The bottom navigation remains visible while the detail page is deep in content, adding another layer of persistent controls.

The recommendation section is pushed too far below the primary content, so the screen does not communicate discovery. The section heading is small relative to the empty space, and the poster cards are large but isolated. The mobile cards have useful metadata, but the action badges and play icons compete with each other.

The top navigation uses a large blank header band with logo, avatar, and menu, but the main content starts without a strong visual anchor. Spacing is generous in the wrong places and compressed around action clusters. The overall app needs a denser content rhythm: one clear page purpose, one primary CTA, one secondary action group, then recommendations and discovery rails.

## Reference direction

Bingr’s home content is recognizable immediately: a prominent featured title, compact metadata and synopsis, then a sequence of current-title rails. The visual hierarchy is content-first and uses fewer competing controls. MAVERO should use the same high-level principle without copying the site: reduce shell chrome, make the featured media/title block unmistakable, put filters/search in one predictable control row, and keep each rail’s action in its heading.

## Proposed system

Use a compact 64–68px desktop header and a 56–60px mobile header. Use a 24px mobile page gutter and 32–40px desktop gutter. Reduce large vertical section margins to 24–32px. Make Discover a clear editorial dashboard: featured hero, “Continue watching” only when populated, compact type switcher, one filter button, and dense horizontal rails with consistent heading/action grammar.

Consolidate action hierarchy. Use one primary action per content block, a compact secondary action group, and move favorite/share into a single overflow/action menu rather than separate floating buttons. Keep recommendation sections close to the detail summary and use the same rail/card component everywhere.

## Live post-deploy verification

The deployed Discover page now has a clear sequence: compact header, featured title block, one search band, one content-type switcher, one filter row, and immediate movie/series/anime rails. The route exposes one View all link per rail and no separate More filters action. The desktop browser screenshot shows the content structure is substantially denser and the page reads as a catalog rather than a blank shell.

The deployed Dune detail page now presents poster, title, metadata, synopsis, Watch now, My list, Share, and compact genre/audio/quality stats in one coherent block. Recommendations begin directly after the content block with a single Keep exploring rail. The duplicated floating heart and separate My list/heart actions from the old screenshot are removed. The detail page has no large empty block between the content block and recommendations in the current desktop verification.

The final Search route now has one search input and one content-type tab row; the old More filters button is removed. Dune results return real TMDB movie and series items plus the expected AniList anime item, with a dense result grid.

The final Profile route uses a compact welcome row, two status cards, and consistent section rails/empty states. It remains a longer library page by nature, but the header and utility cards no longer create the prior oversized spacing. The page retains local/cloud library semantics and the separate CineLog promotion without changing data behavior.
